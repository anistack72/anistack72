# Community discovery and influence

Discovery samples up to 30 contributors from each approved project (Ollama, Tauri and Vitest), then inspects at most 12 profiles and their recent public repositories per run. It prioritizes candidates not already followed so existing leaders cannot indefinitely consume every inspection slot. This is a bounded sample, not a global ranking of GitHub accounts.

Relevant project contributors may include established leaders and smaller technical peers. Selection requires matching technical interests and recent public work. The report records an observed follower count as `audience_followers`; it does not add a popularity bonus to relevance. `follow_back_probability` is explicitly unknown. No account is removed because it did not reciprocate, and the system does not solicit reciprocal stars or followers.

Kelly Blincoe, Jyoti Sheoran, Sean Goggins, Eva Petakovic and Daniela Damian studied 800 survey respondents and 199 popular GitHub users in [Understanding the Popular Users: Following, Affiliation Influence and Leadership on GitHub](https://kblincoe.github.io/publications/2015_IST_Blincoe.pdf). They found that popular users can direct followers toward projects. This historical study does not establish a present-day follow-back conversion rate or prove that following a large account causes it to promote the follower's repositories. Treating these leaders as sources of relevant technical work is our engineering interpretation, not a proven acquisition tactic.

The daily relationship collector records actual newly observed and lost followers. Snapshot changes do not establish which action caused them. The follower count of a candidate is not the number of followers this account acquired. GitHub prohibits [disruptive high-volume following](https://docs.github.com/en/site-policy/acceptable-use-policies/github-disrupting-the-experience-of-other-users); no configured daily ceiling is an assurance of platform approval.
