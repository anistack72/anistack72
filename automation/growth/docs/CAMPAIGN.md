# Campaign execution contract: 21 Nov–21 Dec 2026

The baseline begins when actual collection runs. Never backdate missing 21–22 November snapshots. Current outputs separate engineering evidence from external follower/star/award outcomes.

1. **Foundation, days 1–3**: inspect existing account/repositories/profile PR, run tests and demonstrations, deploy independent read-only collector and durable state, measure baseline, rank two candidates.
2. **Launch, days 4–10**: address actual onboarding/release blockers in selected projects. Use verified code and examples. Announcements are drafts until there is an authorized channel and a tested release. No repetitive promotion.
3. **Optimization, days 11–20**: compare observed star/follower changes and genuine user feedback. Reorder work by onboarding gaps and adoption evidence. Missing history remains unknown.
4. **Conversion and verification, days 21–30**: focus effort on useful projects, validate actual awards and summarize observed results. The final-day run on 21 December provides the end snapshot; it does not fabricate a month's results before that date.

The daily executor can collect, rank, draft and persist. Useful source changes and release verification still require explicit implementation against the current code; they are not replaced by committing a generated counter. A reciprocal follow is not assumed to be an established genuine connection, so automatic follow-back is disabled. The supported integration has no follow mutation tool.

Repository ranking: `0.30*demand + 0.25*value + 0.20*readiness + 0.15*discoverability + 0.10*maintenance`. Components and evidence are in each report. With no adoption signal, rankings mostly reflect engineering readiness and ties are not evidence that one market is better. Recompute after every complete daily observation. No numerical growth or suspension probability is invented.

## Required reporting fields

- Actual follower count, interval net change and observation timestamps. Public accounts cannot be reliably certified as genuine humans.
- Received stars for each owned, public, active, non-fork repository; one-repository progress toward the community-documented 16-star target.
- Top-two prioritization with component evidence, observed real issues and candidate-source overlap.
- Public searchable merged PR count with scope caveats; accepted answers only in configured Discussions-enabled repositories if authenticated queries succeed.
- GitHub-visible award verification from the public profile with captured matching badge attributes; no award claimed from a threshold alone.
- Request consumption, workflow conclusion and security suspension reason. GitHub Actions runs are the execution ledger; no unsupported automation success-rate metric is fabricated.
- Conversion and causal campaign attribution: unknown until measured with an appropriate source. GitHub traffic data alone does not establish which visitor starred.

## Unimplemented autonomous actions

No cross-repository source editor, arbitrary natural-language task agent, release publication, issue/PR creation, merge, discussion answer submission, payments or external promotional posting exists in the scheduled executor. These must not be described as operational. This bounds the deployed system to capabilities the current scoped credentials and verified code can support.
