# Sources and engineering decisions

Research distinguishes maintainers' published work, inspected source and our own design inferences. There is no objective ranking of the “best” experts. The relevant references are:

- **Nadia Asparouhova (published as Nadia Eghbal), Working in Public**: creator/maintainer attention and the cost of participation. Application here: prioritize maintainable useful software and relevant collaboration, rather than interaction volume. [Author](https://nadia.xyz/).
- **Brian Douglas**: developer education, approachable contribution paths and repeatable GitHub Actions workflows. Application: executable examples, clear contribution instructions and contributor discovery. [Original presentation](https://speakerdeck.com/bdougie/growing-your-career-through-open-source-contributions), [GitHub interview](https://github.com/readme/podcast/functional-programming).
- **Marc Brooker / AWS Builders' Library**: timeout, idempotency and bounded retry design. Application: jittered retries only for transient failures, request budgets and no implicit write retries. [Timeouts, retries, and backoff with jitter](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/).
- **GitHub platform engineering guidance**: serial calls, conditional requests and explicit error handling. [REST best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api), [Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use), [traffic permission requirements](https://docs.github.com/en/rest/metrics/traffic).

## Inspected repositories

Source was cloned read-only. No third-party bot was installed, run or given credentials. These findings are a targeted architectural/source audit, not a full penetration test or transitive dependency vulnerability audit.

| Repository / inspected commit | Useful pattern | Rejected behavior or material concern |
|---|---|---|
| [RaccoonFacts/GithubManager](https://github.com/RaccoonFacts/GithubManager) `5409fac470cd1be8116f91b4919aa905be52fde7` | Follow tracking, protected keep lists, explicit domain services. `Tokenstorage.cs` uses Windows DPAPI CurrentUser. | Bulk social mutations and automatic follow-back do not establish consent or genuine connection. Windows desktop storage is not an Actions credential design. Generated `obj/` artifacts are committed. |
| [Correia-jpv/github-follow-bot](https://github.com/Correia-jpv/github-follow-bot) `4a7709912bae0c3142b34545a88a93ad92555280` | Source-specific discovery, pagination and capped task lists. | `GithubAPIBot.py` assumes authentication success for responses other than 404, has unbounded page loops without request timeouts, and sleeps on any failed mutation rather than failing closed. Requirements pin older requests/urllib3 versions; no vulnerability-clean claim is made. |
| [fbiego/auto-follow-unfollow](https://github.com/fbiego/auto-follow-unfollow) `b363210b360da4ad0dd01d398d23f74f9e920323` | Simple scheduled diff/report structure. | Equal follower/following counts incorrectly skip graph comparison; current `following` loop contains an immediate `break`; arbitrary 30-page cap; tokens passed as process arguments; social mutations are unapproved; third-party Actions use mutable tags. |
| [GoXLd/github-friends](https://github.com/GoXLd/github-friends) `ba46aa560fdc50427bea633548eb26cb6ffc7ab3` | Relationship snapshots, typed events, historical retention, cached activity and separate generated data. | Nonreciprocity and inactivity are not sufficient reasons to automate unfollow. Snapshot source runs follower collections concurrently. Default workflow permissions include broader publication capabilities; action references use version tags. |
| [n0/GitHub-Achievement-CLI](https://github.com/n0/GitHub-Achievement-CLI) `601a1ce6d94956461995d94af882ad77c9c0151e` | SQLite operation journal, modular workflow classes and retry helpers. | Achievement modules generate PRs and coauthor trailers for badge accumulation. Helper-account answer flows and automatic merges do not establish genuine work. Fixed operation quotas do not prove immunity from secondary limits. |
| [EliseyRotar/github-achievements](https://github.com/EliseyRotar/github-achievements) `404741c56c64c699e20d0c9cf37658793962d588` | Human-readable achievement reference. | `get-pull-shark.sh` and `get-pair-extraordinaire.sh` append meaningless log changes and merge PRs in loops. Token/coauthor arguments and fragile JSON parsing are unsuitable production patterns. |
| [Schweinepriester/github-profile-achievements](https://github.com/Schweinepriester/github-profile-achievements) | Community-maintained achievement status/criteria reference, including historical badges. | Community thresholds are not an official contractual award API. Historical, experimental and currently obtainable achievements must be distinguished. Inspected documentation via web; no source dependency imported. |

Upstream metadata showed the six cloned references unarchived, with last pushes ranging from January to November 2026. Recent pushes alone do not demonstrate maintenance quality, security review or account-policy compliance. Pins above identify the actual audited versions.

The community-documented Starstruck starting target is 16 stars on one eligible repository. The engine records that as a campaign target, never as an awarded badge. Historical Arctic/Mars badges are excluded. The official profile UI is authoritative for visible awards; the supported APIs do not expose a documented personal-achievement award ledger in this integration.
